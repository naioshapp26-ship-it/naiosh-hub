## الهدف

صفحة **موافقات المدير الأعلى** هي مركز الاعتماد الحقيقي لكل عملية تتطلب موافقة القائد، دون ضياع طلبات في `localStorage` ودون خلط مع صناديق المختصين.

| المستوى | أمثلة | الوجهة |
|---|---|---|
| المدير الأعلى (HA) | تسجيل منصة، استئجار نظام، منح/تغيير أدوار حساسة، إيقاف هوية، مكافآت تتطلب اعتماد القائد | `hub_higher_approvals` + صفحة الموافقات |
| موظف مختص | شحن محفظة، مراجعة مقالات، إعلانات، باقات، قرارات Core Intelligence غير «أعلى» | صناديق/مسارات المختص — **لا** تُحقن في صندوق المدير الأعلى |

## ما نجح محليًا

- إنشاء تسجيل → `approvalId` → ظهور في القائمة → موافقة → تفعيل المنحة.
- إنشاء دائم لـ role / identity / reward عبر مكتبة السيرفر.
- مسار العميل للموظفين ينتظر السيرفر ولا يعلن نجاحًا عند فشل الحفظ.
- مزامنة `local-only` عند hydrate + backfill للأيتام.

## ما فشل / غير مثبت

- لا فشل معروف في المسارات المحلية الأساسية بعد هذا التوسيع.
- **لم يُختبر على الإنتاج** أي رحلة: حساب مختلف → صندوق القائد → قرار → تحديث الأصل → إعادة دخول.
