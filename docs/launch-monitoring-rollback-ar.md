# مراقبة الأخطاء وخطة التراجع — إطلاق www.naioshhub.com

## مراقبة أثناء الإطلاق المحدود (≤50 عميل/يوم · 48 ساعة)

1. **صحة الخدمة (كل 5–15 دقيقة)**  
   `GET https://www.naioshhub.com/api/health`  
   يجب: `ok: true` · `environment.ok: true` · `failed: []` · `database.ok: true`

2. **سجلات Railway**  
   مشروع الإنتاج → خدمة `naiosh-hub` → **Deployments / Logs**  
   راقب: 5xx متكررة، أخطاء Postgres، timeouts، فشل SSO.

3. **مسارات حساسة**  
   - تسجيل/دخول عميل  
   - إنشاء طلب استشارة / شكوى / تذكرة  
   - ظهورها في قوائم الموظفين  
   - رفض قرار HA بدور غير مخوّل (403 متوقع)

4. **لا تُفعَّل المدفوعات** أثناء الإطلاق المحدود إلا بموافقة صريحة من المالك.

## خطة تراجع عن نشر معيب

1. Railway → خدمة `naiosh-hub` → **Deployments**.  
2. اختر آخر نشر **سليم معروف** قبل العطل.  
3. **Rollback / Redeploy** لذلك النشر.  
4. أعد فحص `/api/health` + تسجيل دخول تجريبي + إنشاء طلب واحد.  
5. إن استمر العطل: أوقف الدومين العام مؤقتًا أو فعّل رسالة صيانة من إعدادات النظام (بدون مسح بيانات).  
6. **ممنوع** استعادة Volume Backup فوق Postgres الإنتاج إلا بقرار طوارئ مكتوب؛ مسار التحقق المعتمد هو restore-lab المعزول.

## ما يُبلغ فورًا (إيقاف قبول عملاء جدد)

- `environment.failed` يتضمن أسرار جلسات/SSO  
- قاعدة البيانات غير متصلة  
- فشل جماعي لتسجيل/دخول العملاء  
- تسرّب بيانات بين حسابات العملاء
