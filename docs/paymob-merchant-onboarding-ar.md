# خطوات إنشاء حساب Paymob (بسيطة) — بدون أسرار في الشات

هذا دليل **تنظيمي فقط**. لا ترسل مفاتيح أو بيانات بنكية أو كلمات مرور في المحادثة.

## أ) ماذا تفعل أنت (بالترتيب)

1. ادخل موقع Paymob الرسمي للمطوّرين/التجار واختر التسجيل كـ **Merchant** في مصر (أو الدولة المسجّل فيها نشاطك).
2. أنشئ حسابًا ببريد الشركة الرسمي واختر **Accept** (بوابة الدفع الإلكتروني).
3. أكمل **KYC / توثيق الهوية** حسب نوع النشاط (انظر الجدول أدناه).
4. بعد الموافقة المبدئية، افتح لوحة التحكم وفعّل بيئة **Test** أولًا (ليس Live).
5. من لوحة التاجر انسخ إلى **Railway Variables فقط** (لا تلصقها هنا):
   - `PAYMOB_API_KEY` (مفتاح Test)
   - `PAYMOB_INTEGRATION_ID`
   - `PAYMOB_IFRAME_ID`
   - `PAYMOB_HMAC_SECRET`
   - `APP_URL` = رابط موقعكم المنشور
   - `HUB_PAYMOB_MODE=test`
   - **لا** تضع `HUB_PAYMOB_LIVE=1` قبل موافقتك الصريحة
6. اضبط Webhook / Processed Callback إلى:  
   `https://YOUR-APP/api/hub/packages/paymob/webhook`
7. أخبر الفريق أن مفاتيح **Test** وُضعت (بدون إرسال القيم) لإعادة اختبار الرحلة على الإنتاج التجريبي.

## ب) مستندات شائعة حسب نوع النشاط (مصر — تحقق دائمًا من طلب Paymob الحالي)

| نوع النشاط | غالبًا يُطلب |
|---|---|
| **شركة / مؤسسة** | سجل تجاري · بطاقة ضريبية · عقد تأسيس/أحدث تعديل · إثبات عنوان · بطاقة الرقم القومي للمفوض · خطاب تفويض بالتوقيع · بيانات حساب بنكي باسم الشركة |
| **منشأة فردية** | سجل تجاري · بطاقة ضريبية · بطاقة الرقم القومي · إثبات عنوان · حساب بنكي باسم صاحب النشاط |
| **نشاط رقمي / خدمات** | بالإضافة لما سبق: وصف الخدمة/الموقع · أحيانًا سياسة استرداد وخصوصية · إثبات أنكم تقدمون الخدمة فعليًا |

> المتطلبات تتغير تجاريًا. اعتبر الجدول **إرشادًا**؛ قائمة Paymob داخل نموذج التسجيل هي المرجع النهائي.

## ج) اختبار vs تحصيل حقيقي

| الوضع | المتغيرات | المال الحقيقي |
|---|---|---|
| **Test (مطلوب أولًا)** | مفاتيح Test + `HUB_PAYMOB_MODE=test` وبدون `HUB_PAYMOB_LIVE` | لا |
| **Live** | مفاتيح Live + `HUB_PAYMOB_MODE=live` + `HUB_PAYMOB_LIVE=1` بموافقتك | نعم |

الكود **يرفض Stub** على بيئة شبيهة بالإنتاج، و**لا يفعّل Live** إلا بالعلم الصريح أعلاه.

## د) ماذا نختبر بعد وضع مفاتيح Test

1. اختيار باقة → ظهور المبلغ النهائي بـ EGP قبل الدفع  
2. دفع Test ناجح → إضافة نقاط مرة واحدة  
3. فشل / إعادة إشعار → بلا تكرار نقاط  
4. شراء خدمة بالنقاط → خصم  
5. استرداد بعد استخدام جزئي → خصم المتاح + تسجيل العجز  
6. ظهور الإيصال في `packages-receipts.html` ولوحة الإدارة  

**لا FULL PASS** قبل رحلة Test مصرّح بها على الإنتاج ثم موافقتك على Live.
