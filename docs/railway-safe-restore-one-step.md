# استعادة الحجزين — خطوة واحدة داخل Railway (بدون رابط عام)

## هل يؤثر على العملاء؟
- **دمج PR / إعادة النشر:** توقف قصير معتاد مثل أي نشر على Railway (ثوانٍ إلى دقيقة تقريبًا أثناء تبديل الحاوية).
- **تشغيل علم الاستعادة:** يسبب إعادة نشر أخرى بنفس الأثر المعتاد.
- **أثناء الاستعادة:** النسخ الاحتياطي والاستعادة يعملان **بعد** فتح المنفذ (لا يمنعان healthcheck). العملية إضافة فقط — لا حذف حجوزات ولا تعديل حسابات.
- **إعادة تشغيل لاحقة والعلم ما زال موجودًا:** تصبح العملية **no-op** (الحجزان موجودان مسبقًا) دون كتابة فوق البيانات. مع ذلك احذف العلم فور ظهور OK.

## الأمان في الكود
| ضمان | كيف |
|---|---|
| لا حذف / لا استبدال للحجوزات الحالية | `restoreMissingBookingsOnly` يضيف المعرّفات الناقصة فقط |
| لا تكرار مدمّر | إن وُجد الحجزان مسبقًا → خروج فوري بدون إعادة كتابة |
| نسخة كاملة قبل الاستعادة | `pg_dump` إن وُجد، وإلا نسخة منطقية لكل جداول `public` + تحقق |
| ثبات بعد النشر | الحجوزات في `hub_meta` + دمج ملف∪قاعدة حسب المعرّف |

## الخطوة المطلوبة منك (صلاحية Railway)

1. **ادمج** [PR #229](https://github.com/naioshapp26-ship-it/naiosh-hub/pull/229) إلى `main` وانتظر اكتمال النشر.
2. Railway → خدمة **naiosh-hub** → **Variables** → أضف:
   - الاسم: `HUB_SAFE_RESTORE_TWO_BOOKINGS`
   - القيمة: `1`
   - احفظ (إعادة نشر تلقائية).
3. في **Deploy Logs** انتظر:
   - `[bookings-safe-restore] backup OK …`
   - `[bookings-safe-restore] OK added=pb-mv5po1cv-x1he3,pb-mv5oximx-9f46e total=…`
4. **احذف** المتغير `HUB_SAFE_RESTORE_TWO_BOOKINGS` فورًا واحفظ.
5. أعد نشرًا خفيفًا أو أعد تشغيل الخدمة مرة واحدة (بدون العلم) للتأكد أن العدد ما زال 4.

لا تفتح رابطًا عامًا لقاعدة البيانات ولا تشارك أسرارًا في الشات.
