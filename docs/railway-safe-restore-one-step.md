# استعادة الحجزين — خطوة واحدة داخل Railway (بدون رابط عام)

لا تحتاج مشاركة أي سر أو فتح قاعدة البيانات للعامة. السكربت يستخدم `DATABASE_URL` الداخلي الموجود أصلًا على الخدمة.

## الخطوة الوحيدة المطلوبة منك

1. **ادمج** PR `#229` إلى `main` (لينشر كود الاستعادة الآمنة).
2. في Railway → خدمة **naiosh-hub** → **Variables**:
   - أضف: `HUB_SAFE_RESTORE_TWO_BOOKINGS` = `1`
   - احفظ (سيُعاد النشر تلقائيًا).
3. من **Deploy Logs** انتظر سطرًا يبدأ بـ:
   - `[bookings-safe-restore] OK`
4. **احذف** المتغير `HUB_SAFE_RESTORE_TWO_BOOKINGS` فورًا بعد النجاح.

> إن أردت اختصارًا: بعد دمج الـ PR، الخطوة العملية الوحيدة هي إضافة `HUB_SAFE_RESTORE_TWO_BOOKINGS=1` ثم حذفه بعد OK.

## ماذا يفعل السكربت داخل Railway
1. نسخة منطقية كاملة لكل جداول Postgres العامة → `/tmp/naiosh-hub-backups/…`
2. التحقق من صلاحية النسخة (تحليل JSON + تطابق عدد الصفوف)
3. استعادة الحجزين المعتمدين فقط إن كانا ناقصين
4. لا يحذف ولا يعدّل أي حجز موجود
5. يكتب سجل تدقيق في `hub_meta` (`platform_bookings_restore_audit_v1`)
